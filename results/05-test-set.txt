ResNet18 on the held-out test set
=================================

Run once, on the finished model, and this is the only time the test set has
been touched. Every choice made along the way, augmentation, epoch count,
architecture, the 0.15 malignant threshold and the 0.60 confidence threshold,
was made by looking at validation. That makes validation no longer impartial:
not because the model saw it, but because I did, a dozen times over.

Model
-----
ResNet18 pretrained on ImageNet, fine-tuned for 15 epochs, best epoch 7.
weights/resnet.pth. Same normalisation and no augmentation at inference.

What the numbers say
--------------------
The drop is small: 1.9 points of recall and 3.3 of accuracy. That is the
result worth having. A dozen decisions were tuned against validation, and if
the test set had come back far worse it would mean those decisions had been
fitted to one particular sample rather than to the problem.

The 0.15 threshold, chosen entirely on validation, holds up: 92.0% recall
against the 93.9% it promised. 25 of 314 malignant lesions go unnoticed, and
383 of 1194 benign ones raise a false alarm.

Melanoma recall is 66.3% under the top-class rule, and 37 melanomas were
called ordinary moles. Under the threshold rule most of those are still
flagged, because the model spreads its uncertainty across the malignant
classes rather than landing on nv outright. That gap between 66.3% and 92.0%
is the whole argument for not taking the top class.

df is 12 images. Its 75% recall means nine of twelve. Nothing about that
number is stable and it should not be quoted without saying so.

This file is the last measurement. Anything tuned after this would need a
fresh test set to be honest about.

Correction (2026-11-01)
-----------------------
The top-class rule section above reports "accuracy 74.9%, against 67.2% for a
model that answers nv every time". The second number is wrong.

67.2% was hard-coded into evaluate.py and printed for every split. It is right
for validation, where 1022 of 1521 images are nv, and wrong here: the test set
holds 967 nv out of 1508, so a model answering nv every time scores 64.1%.

The error understated the model rather than flattering it. Against the correct
baseline, 74.9% accuracy is 10.8 points of margin, not the 7.7 this file
implied.

Nothing measured on the model changes. Every other figure here stands, and so
does the 67.2% in results/01 through results/04, which are all validation runs.
The baseline is now computed from the labels of whichever split is being
scored, so it cannot drift away from the data again.

Confidence intervals (2026-11-03)
---------------------------------
Every figure above is a proportion measured on a finite sample, so each
one carries a range it could plausibly have landed in. Adding those ranges
needs no new measurement: a Wilson interval is arithmetic on the two counts
already printed here, so the test set is still at the one run recorded at
the top of this file.

What the numbers say
--------------------
The headline recall holds up. 92.0% with a range of 88.5% to 94.5% is a
number worth quoting, and the 93.9% validation promised sits inside it.

The per-class table is where this changes something. Until now it gave
every class equal weight, and the ranges show they are nothing alike. nv
rests on 967 images and moves 4.7 points. df rests on 12 and moves 44.3.
Its 75.0% recall is anywhere from 46.8% to 91.1%, which spans 'barely
better than a coin' to 'excellent'. The number is not wrong, it is close
to uninformative, and quoting it without this range implies a precision
that twelve images cannot carry.

vasc is the same story with the opposite sign. 100.0% recall looks
perfect and means 20 of 20, which is consistent with a true rate as low
as 83.9%. A single miss would have made it 95%.

Nothing measured changes. These are ranges around figures already
recorded, computed from the counts in this file.
